~/enjoy/about.txt

enjoy

Personal computing as a warm hobby. Every element is a window or a desk object - a 2px ink outline, a surface fill and a hard offset shadow - sitting on a sunny desk under big lazy waves. One mono face does all the talking.

Two things to hold on to. Depth is a hard offset, never a blur: 3px for a window, 2px for a control, and pressing a control takes its shadow away. And there is exactly one saturated field per screen - --feature - so everything else stays soft enough for that one pane to be heard.

Colour Parts Screen Rules
~/enjoy/read-this-first.txt

Read this first

  1. These values are the system. Every number on this page exists in css/enjoy-core.css. Use the tokens; do not invent parallel ones.
  2. Search for an existing part before building a second one. Almost everything is a window, a button, a meter or a row.
  3. No ad-hoc values. No raw hex, no one-off sizes, no new easing curve. Every outline is --line, every shadow is one of the three offsets.
  4. Token names are roles. --tint is the soft fill, not "the aqua"; in the dark theme it is a deep teal and the name is still true.
  5. --feature appears once per screen. It is a content pane, never chrome, a button or an accent. --live is a dot, never a fill or a text colour.
  6. No blur, no gradient, no second typeface. These three refusals are the system.

~/enjoy/04-form

Form

Three moves give every object its silhouette: one 2px ink outline, a friendly radius, and a hard offset shadow. Nothing else - no hairlines, no second border weight, no blur.

radii

--r-win10px
Windows, the screen stage.
--r-ctl8px
Buttons, fields, the menu bar, notes.
--r-knob6px
The toggle knob, tooltips, icon labels.
--r-pill999px
Chips, meter tracks, the toggle track.

depth

--shadow-win: 3px 3px 0
--shadow-lift: hovered control
--shadow-ctl: 2px 2px 0
pressed: no shadow, sunk 2px
disabled: dashed, no shadow
why A hard offset is a physical promise. The shadow sits exactly where a control will land when you press it - 2px down and 2px right - so the press reads as the object meeting the desk. A blurred shadow cannot make that promise; it has no edge to land on.
~/enjoy/05-motion

Motion

Cozy and tiny. Controls lift and sink in 80ms, the readout's colon ticks once a second, and that is all. Only transform, box-shadow, opacity and a fill colour are allowed to move.

the tick, 1s steps
tokenvaluewhere
--t-press80msButton lift and sink, toggle knob, tooltip fade. Seen constantly, so kept almost instant.
--easeease-outThe only curve. Do not introduce a second.
--t-blink1s, steps(1, end)The readout's colon. A step, not a fade - clocks tick.
hovertranslate(-1px, -1px)Plus --shadow-lift. The largest displacement a control ever makes upward.
presstranslate(2px, 2px)Shadow removed. The control lands on its own shadow.
why 80ms is short enough to feel like a click, not an animation. A button that takes a quarter second to sink feels soft and far away; the desk wants objects that answer immediately. Under prefers-reduced-motion the tick stops, transitions drop to zero, and the page is still complete.
~/enjoy/06-screen

Screen

One optional surface treatment: the wallpaper tide. The desk's wave wallpaper comes alive - two lazy waves drift, the front one wears the system's ink outline, and an outlined buoy rides it. Move across the right-hand stage: the tide leans toward the pointer and the buoy follows along the crest.

Static fallback - flat SVG, the same tokens
Live - move the pointer across it

uniformvaluewhat it does
uDrift0.12Wave speed. Slow enough that the tide reads as wallpaper, not weather.
uSwell0.6How far the crest leans toward the pointer's height. The back wave leans half as far.

uGround, uTint, uTint2, uInk, uShadetokensRead from --ground, --tint, --tint-2, --ink, --shadow-ink at runtime, and re-read on every theme change.
springk 40 / d 7The pointer is followed on a spring, softer than a control's, so the tide has weight and settles.
why The shader is built so it cannot draw a gradient. The system refuses gradients, so every region is a flat token colour - ground, half-tint, tint, tint-2, ink - and the only in-between pixels are the one-pixel antialiased edges. It is enhancement only: the static SVG under the canvas is the complete design, the canvas stays transparent until its first frame, it stops rendering off screen, and under prefers-reduced-motion it draws one settled frame identical to the SVG and never starts a loop.

Where it belongs: an empty frame, a hero behind a readout, a screen with nothing in it yet. Not behind body text, and never on the same screen as a feature pane - the tide is soft on purpose, and the feature field should not have to compete with moving water.

~/enjoy/10-rules

Rules

The refusals matter more than the permissions.

do.txt
  • Put every group in a window, with a title that names it.
  • Keep every outline at --line (2px) in ink.
  • Keep every shadow a hard offset: 3px for windows, 2px for controls, gone on press.
  • Spend --feature once per screen, on a content pane, with type at 24px or more.
  • Use lowercase for actions and Title Case for things.
  • Check both themes with the menu bar toggle. Dark is hand-authored, not derived.
do-not.txt
  • Add a blurred shadow. Ever.
  • Add a gradient. Flat fills only - the shader included.
  • Add a hairline or a second border weight.
  • Add a second typeface, or set anything in all-caps.
  • Use --feature for chrome, buttons or accents, or put small text on it.
  • Use --live as a fill or a text colour. It is a dot.
  • Run the tide behind body text or beside a feature pane.
